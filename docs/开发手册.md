# 开发手册

## 1. 结构与运行边界

`saes.py` 提供纯算法与编码函数；`app.py` 负责 HTTP、格式校验和场景编排；`static/` 提供 GUI。`tests/reference_cipher.py` 是按矩阵操作独立转写的测试参考实现，不调用被测算法函数。`verify.py` 生成可复现结果。

Python 运行最低版本为 3.10，应用运行只依赖标准库。前端使用现代浏览器支持的原生 JavaScript，不需要打包步骤。服务只绑定 `127.0.0.1`；静态文件采用固定白名单，不提供目录列表或源码下载接口。

## 2. S-AES 标准约定

依据用户提供附录 D 的 D.1–D.3：

- 分组 16 bits，原始密钥 16 bits，加密两轮。
- 从高到低四个半字节 `n0,n1,n2,n3` 按列组成 `[[n0,n2],[n1,n3]]`。
- 有限域为 GF(2^4)，模多项式 `x^4+x+1`，二进制 `10011`。
- S 盒按高两位选行、低两位选列，展平为 `9 4 A B D 1 8 5 6 2 0 3 C E F 7`。
- 逆 S 盒为 `A 5 9 B 1 7 8 F 6 0 2 3 C 4 D E`。
- 行移位交换矩阵第二行两个半字节，逆操作相同。
- 列混淆矩阵 `[[1,4],[4,1]]`，逆矩阵 `[[9,2],[2,9]]`，运算均在上述有限域内。
- 轮常数 `RCON1=80`、`RCON2=30`（HEX）。

密钥扩展按字节拆分：

```text
w0 = K 的高 8 位，w1 = K 的低 8 位
w2 = w0 XOR 80 XOR SubNib(RotNib(w1))
w3 = w2 XOR w1
w4 = w2 XOR 30 XOR SubNib(RotNib(w3))
w5 = w4 XOR w3
K0 = w0 || w1，K1 = w2 || w3，K2 = w4 || w5
```

附录 D.3 例：`K=2D55`，得到 `K0=2D55, K1=BCE9, K2=A34A`。

```text
加密：AddKey(K0), SubNib, ShiftRows, MixColumns, AddKey(K1), SubNib, ShiftRows, AddKey(K2)
解密：AddKey(K2), InvShiftRows, InvSubNib, AddKey(K1), InvMixColumns, InvShiftRows, InvSubNib, AddKey(K0)
```

第二轮不进行列混淆。轮密钥扩展使用有上限的缓存加速重复调用；并对公开块函数输入作严格整数范围检查，不允许隐式截断或 bool 充当分组。

## 3. Python 接口

均可从 `saes` 导入。块与子密钥是 `0..65535` 的整数，错误输入抛 `ValueError`。

| 接口 | 返回/用途 |
| --- | --- |
| `parse_word(text, fmt='hex')` | 解析恰好 4 位 HEX 或 16 位二进制，可带空格 |
| `gf_multiply(a,b)` | GF(2^4) 乘法，参数 0..15 |
| `expand_key(key)` | 三个 16-bit 轮密钥的 tuple |
| `substitute(state, inverse=False)` | 半字节替代 |
| `shift_rows(state)` | 行移位/逆行移位 |
| `mix_columns(state, inverse=False)` | 列混淆/逆列混淆 |
| `encrypt_block(plaintext,key)` | 一个 16-bit 密文 |
| `decrypt_block(ciphertext,key)` | 一个 16-bit 明文 |
| `trace_block(value,key,decrypt=False)` | 9 项步骤，含名称、HEX、binary、2×2 矩阵 |
| `double_encrypt(p,k1,k2)` | `E(k2,E(k1,p))` |
| `double_decrypt(c,k1,k2)` | `D(k1,D(k2,c))` |
| `triple_encrypt(p,k1,k2,k3=None)` | EDE，省略 k3 时使用 k1 |
| `triple_decrypt(c,k1,k2,k3=None)` | 相反顺序的 DED |
| `meet_in_the_middle(pairs)` | 完整两侧密钥搜索、所有幸存候选与统计 |
| `pad_bytes(data)` / `unpad_bytes(data)` | 2 字节块的 PKCS#7 |
| `encrypt_bytes(data,key)` / `decrypt_bytes(data,key)` | 逐分组 ECB 字节消息，自动填充/去填充 |
| `cbc_encrypt(data,key,iv)` | bytes 密文，不含 IV 前缀 |
| `cbc_decrypt(data,key,iv,unpad=True)` | bytes 明文；unpad=False 保留原始填充 |

低层变换函数 `substitute/shift_rows/mix_columns` 供内部组合，调用者应确保 state 是有效 16-bit 整数。外部输入应通过块函数或服务层。

## 4. 多重加密和 MITM

组合密钥从左到右解析，每 16 bits 为一个子密钥。32-bit EDE 使用 `K3=K1`；48-bit EDE 使用独立 K3。

MITM 接收 1–8 对 16-bit 明密文。为第一组建立 `E(K1,P)` 到所有 K1 的哈希桶，对 K2 枚举 `D(K2,C)`，保留桶内所有匹配 K1，随后用其他已知对筛选。相同中间值允许对应多个 K1，不能覆盖碰撞。

建表和反向搜索各执行 2^16 次核心变换，空间约 O(2^16)；另需验证碰撞候选，成本与候选数、已知对数相关。没有把密钥空间缩小到测试区间，没有把演示密钥传入攻击函数。单对不保证唯一恢复。服务层用进程内互斥锁限制同时执行一个 MITM 请求。

## 5. 编码、CBC 和篡改

明文按 ASCII 编码为 bytes，两字节分组使用大端序。PKCS#7 的块长是 2，填充总会追加，避免零填充丢失真实末尾零字节。

加密密文是任意 bytes。接口提供 HEX、Latin-1 原始字符和其 JSON 转义表示。GUI 仅将 HEX 或 JSON 转义回填 textarea，避免 CR 归一化。解密格式 `escaped` 应先解析 JSON 字符串，再按 Latin-1 编码。

CBC 使用 `C0=IV, Ci=E(K,Pi XOR C(i-1))`，解密 `Pi=D(K,Ci) XOR C(i-1)`。空 IV 仅在加密时自动生成 `secrets.randbits(16)`；解密必须显式提供 IV。IV 与密文分开输出，不附加到密文前。

篡改接口仅修改指定的一个密文分组，可 XOR 或替换。原始、修改后的密文分别以 `unpad=False` 解密，再逐组比较。修改 Ci 会使 Pi 非线性改变、P(i+1) 按掩码翻转，后续不变。修改最后一个密文分组可能破坏填充，比较仍保留全部原始字节。该机制不提供消息认证。

## 6. HTTP API

所有计算接口接受 JSON object，返回 JSON object。成功 200；参数错误/无效 JSON 400；未知路径 404；非 JSON Content-Type 415；过大请求 413；非本地主机或来源 403。请求上限 128 KiB，明文上限 8192 ASCII 字节，密文上限 8194 字节，分别为 HEX/JSON 转义表示预留长度。

| POST 路径 | 参数 | 主要响应 |
| --- | --- | --- |
| `/api/block` | action, data, key, format(hex/bin，默认hex) | hex, binary, trace, round_keys |
| `/api/cross` | vectors:[{plaintext,key,ciphertext}] | rows, passed, total |
| `/api/text` | action, data, key(HEX), representation(hex/escaped/latin1) | hex, latin1, escaped, blocks, byte_length；解密还含 text |
| `/api/multiple` | action, mode(double/triple32/triple48), data, key, format | hex, binary, keys, mode |
| `/api/pairs` | key(32 bits), format | 3 组固定明文的双重 EE 已知对，仅用于生成演示数据 |
| `/api/mitm` | pairs:[{plaintext,ciphertext}]，HEX | keys（组合密钥HEX数组）, candidate_count, searched_per_side, first_pair_matches, middle_values, elapsed_seconds |
| `/api/iv` | {} | iv(4位HEX) |
| `/api/cbc` | action, data, key, iv，密文表示可选 | 字节结果及 iv |
| `/api/tamper` | data(密文), key, iv, index(从0起), change(4位HEX), operation(xor/replace) | 原始/修改密文、blocks 比较、padding_valid、原始字节转义 |

`action` 只能是 `encrypt` 或 `decrypt`。字符串加密时忽略 representation，始终把 data 当作 ASCII 明文。`GET /vectors.json` 返回可交换测试向量。

例如：

```bash
curl http://127.0.0.1:8765/api/block \
  -H 'Content-Type: application/json' \
  -d '{"action":"encrypt","data":"D728","key":"4AF5"}'
```

## 7. 验证和维护

```bash
python3 -m unittest discover -v
python3 verify.py
node --check static/app.js  # 开发时可选，运行应用无需 Node
```

可选开发工具 coverage、ruff 不属于运行依赖：

```bash
uv run --with coverage coverage run -m unittest discover
uv run --with coverage coverage report -m
uv run --with ruff ruff check saes.py app.py verify.py tests --select E9,F63,F7,F82,F401
```

当前覆盖率文件统计 `saes.py` 和 `app.py`，不将独立参考实现计入生产代码覆盖率。浏览器验证应包含五关、ASCII 转义往返、非法输入反馈、结果导出、桌面与移动宽度、CBC 逐组对比。

维护算法时先核对教材常量与矩阵列序，再运行附录变换算例及独立参考实现对照，避免仅靠加解密自洽掩盖标准错误。
