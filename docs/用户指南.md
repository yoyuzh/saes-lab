# 用户指南

## 1. 启动

需要 Python 3.10+ 和现代浏览器。进入本目录运行 `python3 app.py`，或在 macOS 双击 `启动实验.command`。Windows 使用 `py -3 app.py` 或 `start.bat`。

界面地址为 `http://127.0.0.1:8765`。若端口占用，使用 `python3 app.py --port 8766`，打开输出的新地址。所有算法在本机 Python 进程内执行，关掉终端会停止服务。程序没有在线外部依赖。

## 2. 基本测试

1. 选择「基本加解密」，输入格式选二进制。
2. 输入分组 `1101011100101000`，密钥 `0100101011110101`。
3. 点击「加密分组」，得到 `0010010011101100`，对应 HEX `24EC`。
4. 把密文填入输入分组，密钥不变，点击「解密分组」，还原 `1101011100101000`。
5. 点击轮变换步骤，右侧矩阵显示相应状态。矩阵按列填充，`D728` 对应第一行 `D 2`、第二行 `7 8`。

切换格式会在输入有效时自动转换。HEX 分组/密钥必须恰好 4 位，二进制必须恰好 16 位，可用空格分隔。不自动截断超长输入。

## 3. 交叉测试

点击「下载交换向量」，将 `saes-vectors.json` 发送给配合测试的小组。双方用相同明文和密钥计算，再把对方生成的向量粘贴到「测试向量 JSON」。

```json
[
  {"plaintext":"D728", "key":"4AF5", "ciphertext":"24EC"},
  {"plaintext":"A749", "key":"2D55", "ciphertext":"C349"}
]
```

点击「执行交叉验证」，表格同时显示实际密文和对预期密文的解密还原。每组只在两者均一致时通过。最多 100 项。误填密文会被明确标为「不一致」。

内置向量和独立参考实现用于本地一致性验证。本项目已另行使用三点水小组提供的仓库源码进行 522 组双向交叉验证，双方版本、运行平台和原始结果见《组间交叉测试记录》。还可将 `artifacts/三点水小组交换向量.json` 粘贴到界面，复核对方程序生成的 10 组固定密文。

## 4. ASCII 字符串

1. 密钥填 `2D55`，输入 `Hello S-AES!`，点击「加密字符串」。
2. HEX 密文为 `E90156CD0E56B7E4EB31D7E223DF`。
3. 选择 HEX 格式，点击「将密文填入输入框」，再点「解密字符串」，还原原文。
4. 也可先选「字节字符的 JSON 转义表示」，再点击回填并解密；完整字符串含双引号，形如 `"\r%#\u00df"`。

明文允许 ASCII 字符，包括空格、换行和字节零，不接受中文。每 2 字节组成一个分组，使用大端序。为保留原长，采用 PKCS#7：奇数长度补 `01`，偶数长度补 `02 02`，空明文也能处理。

任意密文字节不保证可打印。不要把转义文本当作原始明文；选择匹配的解密格式。字节字符输入采用 JSON 转义以避免浏览器把回车字节改成换行。

单条明文上限 8192 字节。不要使用真实密码等敏感信息演示。结果 JSON 可能包含明文或演示密钥，分享前自行检查。

## 5. 双重与三重加密

分组始终为 16 bits。组合密钥从左到右切分为 K1、K2、K3，每个子密钥为 16 bits。

| 模式 | 密钥 HEX 示例 | 加密定义 | P=D728 的密文 |
| --- | --- | --- | --- |
| 双重 EE | F123FE98 | E(K2, E(K1, P)) | 3476 |
| 三重 EDE / 32 bits | F123FE98 | E(K1, D(K2, E(K1, P))) | 418A |
| 三重 EDE / 48 bits | F123FE985678 | E(K3, D(K2, E(K1, P))) | 8913 |

解密时保持模式和密钥一致，将密文填入「16-bit 分组」，点击「多重解密」。两种三重模式均支持 HEX 或二进制输入。

### 中间相遇攻击

仅针对双重 **EE** 模式。点击「生成演示数据」从左侧前两个子密钥生成已知对：

```text
D728 3476
1234 BC23
FFFF 5EA4
```

攻击只接收这些明密文对。点击「搜索完整密钥空间」，两侧分别枚举 `0000` 到 `FFFF`，得到候选 `F123FE98`。支持 1–8 组已知对。

仅使用第一组时存在 65,568 个候选，不能认定第一个就是原密钥。增加不同明文的已知对可消除大多数歧义。界面显示前 100 个候选，下载 JSON 可获取全部结果，不截断算法的候选集合。

## 6. CBC 与篡改

1. 填密钥 `2D55`、IV `1234`、明文 `ABCDEFGH`。
2. 点击「CBC 加密」，得到 `75A3EB0B27DE693206D6`，密文自动进入右侧篡改区。
3. 点击回填，再点「CBC 解密」，还原 `ABCDEFGH`。
4. 选择篡改分组 `0`、方式「异或位翻转」、掩码 `0001`，点击「篡改并比较解密结果」。
5. 第 0 明文分组由 `4142` 变为 `3147`；第 1 分组由 `4344` 变为 `4345`；第 2 分组以后保持不变。
6. 将方式改为「替换整个分组」，可把选中的密文分组换成指定 16-bit 值。

IV 留空时，加密会自动生成 16-bit 随机值；也可点「生成随机 IV」。解密必须填入加密时共享的 IV。本程序将 IV 单独输出，**不会自动拼接到密文**，交换消息时需一起发送。

篡改对比使用左侧当前密钥和 IV，原密文与篡改密文分别解密，保留填充字节用于观察。普通解密遇到无效填充会报错，篡改实验则仍可展示全部原始分组。

CBC 不认证消息。首组被修改而尾部填充有效时，普通解密仍可能返回被修改内容。不要把「填充有效」当作「没有被篡改」。

## 7. 保存与排错

页面底部「下载本次结果 JSON」保存最近一次成功运算的输出。计算失败会关闭导出，避免下载旧结果。刷新页面会清空本次状态。

| 现象 | 处理 |
| --- | --- |
| 16-bit 输入错误 | 检查输入格式、位数和字符，HEX 4 位、二进制 16 位 |
| PKCS#7 填充无效 | 核对密钥、IV、密文完整性；篡改后的密文可能无法正常去填充 |
| 解密结果不是 ASCII | 核对密钥/IV，或改用篡改实验查看原始分组 |
| 多个 MITM 候选 | 增加使用同一密钥加密的不同明文对 |
| MITM 没有候选 | 检查是否误用了 EDE 密文、不同密钥的已知对或输错数据 |
| 浏览器无法连接 | 确认 Python 服务仍运行，使用终端显示的端口 |
